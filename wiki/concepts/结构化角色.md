# 结构化角色

## 定义
结构化角色是一种利用[[concepts/Chat-Template|聊天模板]]中预定义的角色体系（`system`、`user`、`assistant`、`tool`）严格区分信息传递路径的防御方法。其核心原理是将系统指令、用户输入、助手回复及工具调用结果分别填入各自对应的角色消息中，使模型能够根据角色边界理解并执行指令，而非将全部文本视为平等内容。通过避免把不可信数据（如用户输入）混入指令文本，结构化角色能够有效地抵御[[concepts/Prompt-Injection|提示注入]]攻击。

## 关键特征
- 严格依赖[[concepts/Chat-Template|Chat Template]]的角色划分，各角色消息承担不同的语义功能
- 将系统级指令与用户或外部数据隔离，防止指令被恶意数据覆盖
- 利用模型对角色语义的内化理解，而不是依靠后置解析来区分内容性质
- 对直接提示注入（用户消息中嵌入伪指令）提供天然屏障，因为用户消息不会被视为系统指令
- 适用于基于聊天补全 API 的大多数现代 LLM 应用场景

## 应用
- **安全聊天应用**：在客服机器人、对话代理中，将系统 prompt 放在 `system` 角色，用户问题放在 `user` 角色，有效阻止用户通过精心构造的输入篡改机器人行为
- **工具调用场景**：在 Agent 框架中，通过将工具返回数据放入 `tool` 角色消息，区分工具输出与用户输入，防止工具返回中的潜在注入
- **辅助标记机制**：结合[[concepts/来源标记|来源标记]]，进一步标注外部内容的来源，增强模型对不可信内容的辨别力
- **LLM 安全评估**：在红队测试中，使用结构化角色基线来评估模型对提示注入的鲁棒性
