# Agent

## 定义
Agent（智能体）指能够自主规划并执行任务的 AI 系统，是企业 AI 应用的核心形态。它不再是简单的对话模型，而是具备了与工具、环境交互并持续完成目标的能力。

## 关键特征
- **自主执行**：能够理解任务目标，自行分解步骤并调用外部工具完成，无需人类逐步指令。
- **简单优先**：构建 Agent 时应从最简方案入手，避免过早引入复杂性与过度抽象。
- **透明性原则**：Agent 的决策链路、工具调用与推理过程应当保持透明，便于人类理解与干预。
- **以 ACI 为中心**：Agent 的能力上限很大程度上取决于 Agent‑Computer Interface（ACI，智能体与计算机的交互接口）的设计质量。模糊或不一致的接口会被模型放大，转化为系统性的行为错误。
- **评估驱动**：持续、高质量的评估机制对 Agent 的性能迭代不可或缺，需要在真实任务中不断校准。
- **实践领先**：在业界术语和概念沉淀之前，工程实践应当先行，通过可工作的系统来定义和检验“什么才是好的 Agent”。

## 应用
- **企业自动化**：作为 AI 应用的核心载体，驱动客服、运维、数据分析等长链条任务的自动化闭环。
- **工具集成与编排**：通过精心设计的工具接口，Agent 能够串联多个后台系统、API 和数据库，实现复杂业务流程的端到端执行。
- **研发辅助**：在代码编写、系统调试、环境管理等场景中，Agent 以“自主助手”的形式参与工作，配合 [[concepts/保持简单|保持简单]] 和 [[concepts/保持透明|保持透明]] 原则提升人机协作效率。

## 相关概念
- [[concepts/ACI|ACI]]：Agent 与计算机的交互接口，决定了工具调用的可靠性与可扩展性。
- [[concepts/保持简单|保持简单]]：Agent 构建的起始原则，避免过早优化与过度设计。
- [[concepts/保持透明|保持透明]]：确保 Agent 行为可解释、可审计的设计准则。
- [[concepts/实践在前，命名在后|实践在前，命名在后]]：强调在概念被广泛命名之前，应当率先通过工程实践来验证 Agent 形态的有效性。
