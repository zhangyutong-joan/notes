# 渐进式披露

## 定义
渐进式披露（Progressive Disclosure）是 Agent Skills 体系中的一种设计原则：不将全部工具/技能的完整定义一次性注入静态 System Prompt 前缀，而是仅在静态前缀中保留工具的名称和简短描述（元数据）。当模型判断需要调用某个工具或技能时，再通过专用机制加载其完整定义与文档，并追加到对话末尾。这种方式在保持前缀缓存稳定性的同时，大幅降低了常驻 token 消耗，使大规模 Agent 系统具备了可扩展的技能加载能力。

## 关键特征
- **前缀极简**：静态前缀只包含工具元数据（名称、一句话描述），不含完整 schema。
- **按需加载**：仅在模型主动识别到调用需求时，才通过一次额外调用或内部机制加载工具的完整定义和说明文档。
- **缓存友好**：由于前缀内容极小且极少变化，模型 API 的提示缓存（Prompt Cache）或 KV 缓存能保持高命中率，提升响应速度并降低成本。
- **动态注入位置**：加载的完整定义追加到对话末尾而非插入前缀，避免破坏已缓存的前缀结构。
- **API 原生支持**：该模式从早期框架层补丁演进为 API 层面的原生能力，不再依赖外部中间件或 hack 实现。
- **可扩展性**：Agent 可以挂载大量工具，但初始 token 占用不随工具数量线性增长，使大规模工具集成为可能。

## 应用
- **大规模 Agent 系统**：当 Agent 需同时识别上百个工具时，渐进式披露可避免前缀爆炸，同时保持模型对工具的理解能力。
- **高并发对话服务**：利用稳定前缀最大化缓存命中，降低每次首 token 的延迟和计算成本。
- **动态工具集**：在对话过程中根据上下文动态挂载或移除工具，而不影响已缓存的静态前缀。
- **企业级 AI 应用**：如 Claude Code 或 Harness AI 助手等环境中，实现按需加载技能，平衡功能丰富性与经济性。
