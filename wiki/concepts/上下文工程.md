# 上下文工程

## 定义
上下文工程（Context Engineering）是由 Anthropic 提出的一种方法论，旨在系统性地组织和管理提供给大语言模型（LLM）的信息。它主张将不同类型的上下文（如系统提示、项目上下文、用户偏好、任务参考、可复用技能）拆解并分发到正确的位置，而不是全部塞入一个长 prompt。这种方法提升了 AI Agent 的准确性、可维护性和可扩展性，是现代 AI 应用开发的重要实践。

## 关键特征
- **信息分类存放**：将系统提示、项目上下文、用户偏好、任务参考、可复用技能等分别管理，避免单一长 prompt。
- **结构化分发与实时调取**：按照 Agent 工作流的需求，在正确的时间注入正确的上下文，实现按需加载。
- **提升可维护性与可扩展性**：上下文模块化后，局部修改不影响整体，方便更新和复用，降低维护成本。
- **由 Anthropic 提出**：源于对 LLM 应用交互模式的设计，被广泛用于 Agent 类产品（如 Claude Code）中。
- **强调“位置正确”**：上下文工程不只关注内容本身，更关注信息应该放在 System Prompt、User Prompt、工具描述还是外部知识库中。

## 应用
- **AI Agent 工作流设计**：在助手或 Agent 启动时，将系统行为规则、项目背景、用户偏好、可调用技能等分离存放，运行时动态组合，从而生成更准确、更符合预期的响应。
- **提升响应一致性与准确性**：防止因 prompt 过长导致模型忽略关键指令，同时减少上下文窗口浪费，使模型聚焦于当前任务所需的最小必要信息。
- **复杂项目开发**：在代码助手、研究助手等场景中，通过上下文工程实现多轮交互的信息持久化和灵活切换，保证 Agent 对不同任务的理解始终基于最新、最相关的上下文。
- **多用户或多场景适配**：将用户级、会话级、项目级的上下文分层管理，便于不同用户或不同场景快速复用基础能力，提高开发效率。
