# 缓存边界

## 定义
缓存边界是提示词设计中的物理标记，用于将系统提示词切分为静态的可缓存前缀与动态的用户/会话特有部分。该边界决定了哪些提示内容可以跨请求共享缓存（前缀部分），从而提升推理效率、降低计算成本，哪些内容必须根据每次请求的上下文变化重新处理（边界之后的部分）。

## 关键特征
- **物理分隔标记**：通常是一个特殊的 token、字符串或模板占位符，在提示词中明确标识“至此以前可缓存，此后不可缓存”。
- **静态与动态分离**：系统提示词在缓存边界之前的内容封装了稳定的角色、规则、工具定义等，之后则附加用户输入、对话历史、实时数据等动态信息。
- **缓存复用性**：前缀部分一经缓存，便可被同一模型实例上的多个请求共享，避免重复计算 KV‑cache 和 token 推理。
- **结构依赖**：缓存边界的位置直接影响提示词的组织方式——所有静态内容必须前置，动态内容后置，破坏了某些情况下“消息交错”的自然结构。
- **成本效益**：合理设置缓存边界能显著降低长对话、多轮交互场景下的计算与延迟开销，是缓存优先设计中的核心权衡点。

## 应用
- **大模型推理服务**：在部署生产级对话系统时，利用缓存边界固定系统提示，使模型在对不同用户的每次调用中只需计算一次前缀，极大提升吞吐量。
- **Agent 框架设计**：将工具说明、角色定义、安全约束等静态信息置于边界前，将任务参数、环境状态等动态信息置于边界后，实现响应速度与可维护性的平衡。
- **成本控制与计费优化**：通过最小化不可缓存内容的长度，减少重复计算的 token 消耗，直接降低 API 调用费用。
- **上下文工程实践**：与[[concepts/Prompt-Cache|Prompt-Cache]]、[[concepts/KV-Cache|KV-Cache]] 等技术协同，指导开发者在编写系统提示词时遵循缓存优先原则，实现架构层面的性能优化。

## 相关概念
- [[concepts/缓存一致性|缓存一致性]]：保证前缀缓存内容不被意外修改，以避免模型行为漂移。
- [[concepts/System-Prompt|System-Prompt]]：被缓存边界所分隔的主要对象，其结构设计直接影响缓存边界的位置与有效性。
- [[concepts/Prompt-Cache|Prompt-Cache]]：利用缓存边界实现的高效提示缓存技术。
- [[concepts/KV-Cache|KV-Cache]]：底层缓存机制，缓存边界的作用最终体现为对 KV‑cache 的复用管理。
