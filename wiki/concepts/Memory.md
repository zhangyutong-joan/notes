# Memory

## 定义
Memory 是在[[concepts/上下文工程|上下文工程]]中代表用户持久性偏好的长期上下文模块。它附着于个人账户，记录用户的常用技术栈、沟通风格、视觉审美等跨项目个性设置，并与项目专属的 `CLAUDE.md` 形成互补，使智能体在不同会话中能够适配用户的习惯与偏好。

## 关键特征
- **跨项目复用**：Memory 不绑定特定项目，而是跟随用户账户，在一次配置后即可在任意对话中生效。
- **用户级上下文**：存储的是用户层面的偏好（如喜欢的语言、代码风格、回复详细程度），而非项目特定的规范。
- **持久性**：偏好信息长期保留，可供后续会话反复读取，避免重复询问。
- **由上下文整理助手管理**：通常由[[concepts/上下文整理助手|上下文整理助手]]（COA）从历史对话中提取并整理成结构化的 Memory。
- **可进化**：随着用户行为的积累，Memory 可以被逐步丰富与修正，实现个人化的服务演进。
- **外围按需读取**：Memory 位于上下文的外围，由 Agent 在需要时读取，避免占用过多上下文窗口，在实现个性化的同时保持效率。
- **跨对话持久化信息层**：不同于一次性的用户提示或 References，Memory 是跨越多次对话的持久化信息层，强调其与瞬态上下文的区别。
## 应用
- **个性化智能体交互**：Agent 读取 Memory 后自动调整回复风格、技术选型建议、语气等，减少用户每次手动说明。
- **上下文连续体验**：在[[concepts/上下文工程|上下文工程]]框架中，Memory 与[[concepts/Skills|Skills]]、[[concepts/结构化角色|结构化角色]]等模块协同，使多次对话保持一致的“身份感”。
- **团队或组织场景**：除个人 Memory 外，类似机制也可扩展到团队偏好，形成组织级的[[concepts/私有Context|私有Context]]，统一协作风格。
- **低摩擦新会话**：即使开始一次全新的会话，用户无需重新交代背景信息，助手即可根据 Memory 提供贴近个人需求的回答。
- **长期合作关系模拟**：Memory 使 Agent 能够模拟人类助手对长期合作关系的理解，是 Agent 高级功能的重要组成部分，帮助助手持续跟踪用户历史与偏好，构建更深层次的信任与默契。
