# Sliding Window

## 定义
Sliding Window（滑动窗口）是一种上下文管理策略，通过仅保留对话历史中最近 N 条消息来限制上下文长度，之前产生的较早消息会被直接丢弃。

## 关键特征
- **固定窗口大小**：仅保留最近 N 条消息，超出窗口上限的旧消息自动被清除。
- **破坏前缀一致性**：每轮滑动都会改变输入序列的前缀，使得先前计算的 [[concepts/KV-Cache|KV Cache]] 无法被复用，导致推理效率大幅下降。
- **上下文信息丢失**：关键的工具调用结果、推理依据或用户早期指令可能在窗口滑动后丢失，影响 Agent 的决策质量。
- **常被归为反模式**：在需要概率性缓存复用的环境下，滑动窗口是“常见的错误上下文管理模式”之一，与“保持前缀稳定”的原则相悖。

## 应用
由于滑动窗口会破坏前缀缓存的稳定性，它通常不被推荐在高性能 LLM 应用中作为主要的上下文管理方法。但在以下场景中仍可能被采用：
- **简单对话机器人**：对缓存复用要求不高，仅需保持最近对话即可。
- **内存极度受限的环境**：当缓存容量无法容纳更复杂的上下文管理（如摘要或缓存感知截断）时。
- **教学与对比案例**：用于说明上下文管理反模式，强调应优先选择能保持前缀一致性的策略（如基于系统提示词的动态注入或前缀稳定修剪）。

## 相关概念
- [[concepts/KV-Cache|KV Cache]]：键值缓存，其复用效率受前缀一致性直接影响。
- [[concepts/缓存一致性|缓存一致性]]：滑动窗口破坏缓存一致性的典型例子。
- [[concepts/动态系统提示词|动态系统提示词]]：一种保持前缀稳定的替代方案，通过将动态信息放入特定缓存段而非整体滑动来避免 KV Cache 失效。
