# 动态系统提示词

## 定义
动态系统提示词（Dynamic System Prompt）是一种在系统提示词中注入动态可变内容（如当前时间、用户状态、会话上下文等）的上下文工程反模式。这种做法会破坏前缀的字节级稳定性，导致 [[concepts/KV-Cache|KV 缓存]] 和 [[concepts/Prompt-Cache|提示缓存]] 完全失效，每次请求都需重新计算全部前缀，增加延迟与成本，被列为上下文工程中“最常见的错误”之一。

## 关键特征
- **破坏前缀稳定性**：系统提示词作为模型输入的固定前缀，其上任何动态变化都会改变整个 token 序列，使缓存无法复用。
- **导致缓存失效**：KV Cache 与 Prompt Cache 依赖前缀的字节级一致；动态注入使缓存命中率降为零。
- **增加推理开销**：每次请求都强制重算前缀，显著提高首 token 延迟与总计算成本。
- **隐蔽性强但危害大**：开发者容易出于便利直接在系统提示词中插入动态变量，却未意识到其对缓存的破坏，长对话或高频场景下影响尤为严重。
- **可修正**：正确做法是将动态信息作为用户消息追加到对话末尾，或仅在真正需要时通过工具调用获取。

## 应用
- **需要动态信息注入的场景**：例如当前时间、用户偏好、会话 ID 等，应避免将其放入 [[concepts/System-Prompt|系统提示词]]，而改为用户消息追加模式，以保持前缀稳定、保证缓存正常工作。
- **与滑动窗口反模式的共同分析**：动态系统提示词和 [[concepts/Sliding-Window|滑动窗口]] 是上下文工程中应全力避免的两种反模式，常联合讨论以强化缓存一致性设计。
- **缓存优化实践**：在实现 Prompt Cache 或 KV Cache 的场景中，识别并消除动态系统提示词是提升系统性能的关键步骤之一，需结合 [[concepts/缓存一致性|缓存一致性]] 原则进行设计审查。
